# `/pb:review` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One procedure, `/pb:review`, that cleans the brain: a weekly unattended routine applies what has one right answer and queues the rest; the interactive command asks the owner the queued items of their competence.

**Architecture:** The judgement lives in one skill (`skills/review/SKILL.md`), vendored for the cloud routine like `sync`. The toolkit only gains the deterministic parts: the queue file `brain/.pb/pending.md` (parse, validate, count), the count line in the Brain updates PR, and small plumbing (state source, schedule validation, retention, one lint exemption). `/pb:lint` and `/pb:questions` are deleted; `PB lint` stays.

**Tech Stack:** Python 3 standard library, `unittest` (run from `tests/`: `cd tests && python3 -m unittest`), Markdown skills.

**Spec:** `docs/specs/2026-11-13-review-design.md`

## Global Constraints

- No new dependency; toolkit output stays JSON.
- Interactive `/pb:review` runs in the working branch and ends with `PB save`; it never commits or pushes.
- The unattended half runs only on `docs/brain` (`PB routine start` … `PB routine finish --skill review`).
- Unattended: never deletes or merges pages, never rewrites a decision body, never edits digests, `.pb/raw/`, `.pb/corrections.md`.
- Queue line format, exact: `- [ ] R<n> · <functional|technical|any> · <TAG> · <pages> · <doubt> · suggested: <action or none> · found: <YYYY-MM-DD>`; a remembered "no": `- [x] R<n> · … · kept: <reason>`.
- Tags: `DUPLICATE`, `CONTRADICTION`, `MOVED`, `OUTDATED`, `SUPERSEDED`, `GLOSSARY`, `QUALITY`, `LINK`, `SCHEMA`, `JIRA`.
- Report file: `brain/.pb/digests/YYYY-MM-DD-review.md`. Default weekly schedule: `0 4 * * 0`.
- Plugin version `0.7.0` (`.claude-plugin/plugin.json`, `scripts/pb_core/__init__.py`, `tests/test_plugin_layout.py`).
- Shipped text is English; no banned words of `test_no_stale_model_in_shipped_text` (notably "review PR").

## Review Focus

1. A hand-edited `pending.md` with a malformed line → `PB validate` reports `bad-pending` with the line number, and the count ignores that line instead of crashing. (Task 2)
2. `pending.md` absent (every brain before the first review) → count is zero, no PR line, no warning. (Task 2)
3. An open question with `area: ux`, or a page with no area → counted as `functional` / `any`. (Task 2)
4. A review report older than `digest_retention_days` → deleted like a digest; a file in `digests/` with another name → untouched. (Task 1)
5. `review` configured in `sources.md` but the vendored `skills/review/SKILL.md` missing → `routine-instructions-missing` warning. (Task 1)

### Task 2: The queue — `pending.md`

**Files:** Create `scripts/pb_core/pending.py`, `tests/test_pending.py`; modify `validate.py`, `cli.py`, `repo.py` (`brain_pr_body`), `gitops.py` (`_brain_pr`), `tests/test_brain_pr.py`.

**Produces:**
- `pending.PATH = ".pb/pending.md"`, `pending.TAGS`, `pending.AREAS = ("functional", "technical", "any")`.
- `pending.read(brain) -> {"items": [{"n", "done", "area", "tag", "text", "line"}], "bad": [{"line", "text"}]}` — a line starting with `- [` that does not match the format is `bad`; other lines are ignored; no file → both empty.
- `pending.waiting(brain) -> {"functional": int, "technical": int, "any": int, "total": int, "report": str | None}` — open (`[ ]`) items by area plus open questions (`status` open or absent; area through `review.page_area`, `ux` → `functional`, none → `any`); `report` is the newest `.pb/digests/*-review.md` as a `brain/…` path.
- `pending.pr_line(waiting) -> str` — `""` when `total` is 0 and there is no report; otherwise `Waiting for a decision (run /pb:review): functional <n>, technical <n>, any <n>. Latest review report: <path>.` (report sentence omitted when none).
- CLI `PB pending` → the `read` result plus `waiting`; `--add 'AREA · TAG · pages · doubt · suggested: …'` appends an open line with the next `R<n>` and today's `found:` and returns it, refusing (`UsageError`) an unknown area or tag; `--done N --kept REASON` ticks line N; `--remove N` deletes it.
- `brain_pr_body(markdown, behind, base, waiting_line="")` — the line, when not empty, goes after the behind notice and before the watched changes.

- [ ] Tests first: parse open, ticked and malformed lines; `waiting` with no file, with `ux` and area-less open questions, ignoring resolved questions; `pr_line` empty and full; CLI add → number increments, bad tag refused; done/remove; `PB validate` → `bad-pending` error naming the line; `brain_pr_body` with and without the line.
- [ ] Implement; `validate` reports each `bad` entry as error `bad-pending` on `.pb/pending.md`; `_brain_pr` passes `pending.pr_line(pending.waiting(brain))`.
- [ ] Run `test_pending`, `test_brain_pr`, `test_validate`, `test_gitops`; all pass.
